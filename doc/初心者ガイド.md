# 初心者ガイド — このテンプレの使い方

データサイエンスを「少し触った程度」でも使えるよう、**何が入っているか**と**Cursor での頼み方**だけに絞って書いています。

技術セットアップの詳細は [TEMPLATE_SETUP.md](../TEMPLATE_SETUP.md)。エージェント向け索引は [AGENTS.md](../AGENTS.md)。

---

## 1. このテンプレは何？

**AI（Cursor）に渡す「分析のルールブック一式」** です。

動画のコード写植や、その場の AI コーディングだけだと、毎回こうなりがちです。

- グラフの日本語が文字化けする
- データを間違ったフォルダに保存する
- 前に直したルールをまた直す

このテンプレは、そういう **毎回同じ手直し** を減らすための土台です。分析の正解を教えるものではなく、**やり方をそろえる** ための道具です。

---

## 2. フォルダのイメージ（これだけ覚えれば OK）

```
data/raw/        … 元データ（触らない・Git に入れない）
notebooks/       … 試す・眺める場所
src/             … うまくいったコードを移す場所
outputs/         … グラフ・表の保存先
doc/agent/       … 「この分析は何のため？」のメモ
.cursor/skills/  … AI への詳しいマニュアル（17 個）
```

| やること | 置き場所 |
|---|---|
| データを置く | `data/raw/` |
| とりあえず試す | `notebooks/` |
| 何度も使う処理 | `src/analysis_project/` |
| グラフ・CSV を出す | `outputs/figures/` や `outputs/tables/` |

---

## 3. 中身の種類（全部覚えなくてよい）

| 種類 | 場所 | 役割 |
|---|---|---|
| ルーター | `AGENTS.md` | 「今何をする？」→ どの skill を見るか |
| 常時ルール | `.cursor/rules/ds_core.mdc` 等 | uv のみ・raw データを触らない 等 |
| 作業別マニュアル | `.cursor/skills/`（10 個） | 可視化・ML・notebook などの詳細 |
| ワークフロー | `.cursor/skills/`（7 個） | 分析計画・EDA・モデリングなどの一連の流れ |
| プロジェクトメモ | `doc/agent/` | データ定義・指標・目的（後から書いてよい） |

**初心者が最初に使うのはワークフロー 7 個と `visualization` だけで十分** です。

---

## 4. Cursor への頼み方（コピペ用）

チャットに **skill 名を書く** のがコツです。

### よく使う依頼文

| やりたいこと | Cursor に貼る文 |
|---|---|
| まず計画 | `plan-analysis skill で、このデータの分析計画を日本語で作って` |
| データを眺める | `run-eda skill で data/raw/（ファイルパス）の EDA を実装して` |
| きれいなグラフ | `visualization skill に従って、（内容）のグラフを outputs/figures/ に保存して` |
| 予測モデル | `run-modeling skill で、（目的変数）を予測するモデルを作って` |
| 結果を文章化 | `summarize-analysis skill で分析結果を日本語でまとめて` |

### タイタニックの例

```text
visualization skill に従って、SIGNATE 形式の train.csv から
性別ごとの生存率を棒グラフにして outputs/figures/ に保存して
```

```text
plan-analysis skill で、タイタニック生存予測の分析計画を日本語で作って。
データは data/raw/titanic/train.csv を想定して
```

```text
run-modeling skill で survived を予測するモデルを作って。
データは data/raw/titanic/train.csv、ベースラインも比較して
```

## 5. おすすめの進め方（3 段階）

### 段階 A: いま進行中のプロジェクトで試す

既に `Data_Science/analysis_titanic` などがある場合、**テンプレを丸ごとコピーしなくてよい**。

1. そのプロジェクトを Cursor で開く
2. テンプレから `.cursor/skills/visualization` など必要なフォルダだけコピー（任意）
3. 上記の「頼み文」でグラフや計画を試す

いちばん効くのは **可視化**（日本語・保存先・棒グラフのルール）です。

### 段階 B: 新しい課題をゼロから始める

Kaggle / SIGNATE の **別問題** に挑むとき。

```powershell
# Documents フォルダで実行
Copy-Item -Recurse dev_templates\ds-analysis-template Data_Science\課題名
cd Data_Science\課題名
uv sync
```

1. CSV を `data/raw/` に置く
2. Cursor で `plan-analysis skill で…` から始める
3. `run-eda` → `run-modeling` → `summarize-analysis` の順でもよい

詳細は [TEMPLATE_SETUP.md](../TEMPLATE_SETUP.md)。

### 段階 C: 慣れてきたら

- `doc/agent/Development/dev_templates/web-static-template/doc/agent/プロジェクト概要.md` … 何のための分析か
- `doc/agent/data-catalog.md` … 列の意味・データの出所
- `doc/agent/metrics-and-definitions.md` … 指標の定義

を少しずつ埋めると、AI の回答が安定します。**最初は空で問題ありません。**

## 6. 過去のやり方との対応

| これまでの経験 | テンプレで代わること |
|---|---|
| 動画を見ながらコード写植 | `run-eda` / `run-modeling` で「何を作るか」を先に決められる |
| アヤメ分類を AI コーディング | `statistical-ml-review` で train/test・評価の確認リスト |
| タイタニックを公式 doc 見ながら可視化 | `visualization` で日本語・保存先・棒グラフのルールが固定 |

写植や AI コーディングは **悪くない** です。テンプレはその **品質をそろえる補助輪** だと思ってください。

## 7. 用語ミニ辞典

| 用語 | ひとこと |
|---|---|
| **uv** | Python パッケージ管理。`uv sync` で環境が揃う |
| **polars** | 表データ処理ライブラリ（pandas に近い）。新規コードはこちら優先 |
| **EDA** | 探索的データ分析。まずデータを眺める作業 |
| **skill** | AI への作業マニュアル 1 件（`.cursor/skills/〇〇/SKILL.md`） |
| **workflow skill** | 分析計画・EDA など、**あなたが明示して** 使う skill（`plan-analysis` 等） |
